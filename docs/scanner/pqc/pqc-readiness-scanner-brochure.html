Application PQC Readiness Scanner Assessment Tool

A source-code and dependency assessment accelerator that finds quantum-vulnerable cryptography touchpoints, separates implementation from reference-only evidence, and turns raw findings into a migration worklist.

Migration Clarity Shows where RSA, ECC, cert, TLS, JWT, SSH, and KMS patterns actually sit in application code and configuration.
Better Prioritization Separates frontend awareness, backend implementation, infrastructure configuration, and reference-only artifacts.
Actionable Planning Produces per-file findings, likely change targets, complexity ratings, CBOM enrichment, and migration work packages.

Why It Matters

Many organizations can produce a crypto inventory, but that still leaves the harder question unanswered: which files, services, certificates, and integration points are most likely to drive post-quantum migration effort?

PQC transitions cut across certificate lifecycles, JWT and token signing, mTLS configuration, SSH operations, KMS dependencies, and code-signing workflows. Teams need evidence that maps these concerns back to real files and likely owners.

This scanner is designed for migration planning, not just inventory. It highlights categories such as `ASYMMETRIC_ALGORITHM`, `CERTIFICATE_USAGE`, `TLS_CONFIGURATION`, `JWT_OR_TOKEN_SIGNING`, `SSH_USAGE`, and `KMS_OR_HSM_ASYMMETRIC` and explains which findings are likely implementation work versus reference-only awareness.
Questions It Answers

Where quantum-vulnerable crypto patterns appear, which files are likely real migration owners, and which findings are configuration, dependency, or reference-only evidence.

Typical Application Tiers

Spring Boot, .NET, Python, Go, Node.js, React, Angular, Kubernetes configuration, package manifests, and certificate or keystore handling code.

Planning Value

Helps architects and delivery teams scope certificate, protocol, signing, and dependency-driven workstreams before detailed remediation begins.

Executive Summary And How The Scanner Works

PQC-Focused Discovery

The scanner uses source patterns, dependency evidence, and file classification heuristics to find likely post-quantum migration touchpoints.

  • Implementation categories such as RSA, ECC, certificates, TLS, JWT, SSH, KMS, and code signing
  • Dependency and CBOM enrichment across JVM, .NET, npm, Go, and Python ecosystems
  • Per-file summaries, likely change targets, and recommended migration actions
  • Reference-only filtering so frontend, docs, and passive dependency files do not get mistaken for primary implementation owners

This helps teams move from general crypto awareness to a more practical answer: what needs review first, by whom, and why.

What The Scanner Produces

The current migration project can scan PII, PQC, or both together while keeping each domain separate in output.

  • --scan pii
  • --scan pqc
  • --scan pii,pqc
  • JSON, CSV, and HTML reporting
  • CBOM import and export support

PQC findings retain their own domain, category totals, complexity distribution, and recommended-action summary so they are not hidden inside PII results.

What It Classifies

Frontend, backend, infrastructure config, test, docs, implementation-heavy files, and reference-only artifacts.

What It Scores

Low, medium, and high PQC migration complexity using findings, integration patterns, and likely implementation ownership.

Why It Helps

Turns crypto discovery into a migration backlog by highlighting likely change targets, work packages, and platform-specific hotspots.

Metrics, Positioning, And Customer Outcome

Important Output Attributes

  • pqc_summary_by_category
  • pqc_migration_classes
  • pqc_likely_change_target
  • pqc_recommended_change_action
  • pqc_complexity_rating
  • pqc_complexity_score
  • dependency_references
  • cbom_components

These fields help teams filter for protocol work, signing work, certificate lifecycle work, and dependency-driven remediation.

Typical Work Packages

  • JWT and application-signing review
  • TLS and certificate lifecycle modernization
  • KMS or HSM dependency review
  • SSH protocol and key-management review
  • Code-signing workflow review
  • Reference-only triage for docs and frontend artifacts

The scanner helps keep these tracks separate so one large crypto backlog does not hide the real sequence of work.

Best Use

Application modernization planning where teams need code-level PQC impact, not only a portfolio inventory.

Where CBOM Helps

CBOM import and export enrich dependency-level understanding and make it easier to compare packaged crypto components with observed source findings.

Thales Fit

The scanner is designed to support Thales-specific recommendation logic and migration conversations around certs, protocols, signing, and key-management transitions.

How It Compares

  • CBOM tools are strongest for baseline machine-readable inventory.
  • Static analysis is strongest for custom crypto rules inside existing developer platforms.
  • Network monitoring is strongest for deployed TLS and certificate posture.
  • Enterprise crypto scanners are strongest for broad asset discovery and posture visibility.
  • This scanner is strongest when teams need source-line attribution, implementation context, effort sizing, likely change targets, and a modernization worklist.

Why Customers Choose It

  • easier to move from findings to planning output
  • better file-level prioritization than inventory-first tools
  • stronger support for likely change targets and recommended actions
  • more useful for multi-tier application analysis
  • better fit for Excel, Power Query, BI, and architecture-review workflows

Customer Outcome

Instead of stopping at "we found RSA, certs, and JWT libraries," customers can review concrete evidence showing which files are likely to require implementation change, which items are mostly reference-only, how crypto dependencies map to source files, and where remediation should begin.

The result is faster scoping, clearer ownership conversations, better sequencing of certificate and protocol work, and more practical PQC migration planning across application and infrastructure teams.

The strongest value of the scanner is not replacing CBOM or enterprise crypto discovery. It is translating those signals, plus source evidence, into an application migration plan.
