Snowflake JDBC Technical Overview

How the Thales Snowflake JDBC wrapper applies policy-aware reveal

The implementation is a wrapper-plus-delegate-driver design. Snowflake JDBC remains responsible for the database connection and SQL execution; the Thales layer intercepts JDBC results and processes only configured protected fields.

Core runtime pattern

  • Delegate driver: the wrapper delegates to the standard Snowflake JDBC driver.
  • JDBC interception: proxies wrap Connection, Statement, and ResultSet.
  • Field selection: object-scoped mappings or default mappings identify protected result columns.
  • Policy call: CRDP or CADP Centralized handles protect/reveal for those configured values.
  • Batching: CRDP result values can be grouped for revealbulk processing.

Runtime Sequence

Connection, query, mapping, and reveal flow

1. Client

Application or database tool

Issues normal Snowflake JDBC connections and SQL.

2. Wrapper

Thales Snowflake driver

Normalizes the URL, applies wrapper configuration, and returns JDBC proxy objects.

3. Delegate

Snowflake JDBC driver

Connects to Snowflake and executes SQL using the current session context.

4. Result interception

Batching result-set proxy

Reads returned fields, resolves object and column mappings, and gathers protected values.

5. Thales service

CRDP or CADP Centralized

Reveals configured values and returns the policy outcome to the client.

Configuration resolution

For a returned field, object-scoped mappings are evaluated first. If the table or view has an applicable protect.object.<name> mapping, that mapping defines the protected columns for the object. Otherwise, the driver uses app.fieldstoprotect.

protect.object.EMPLOYEES_EXTERNAL= email|tag.char.external, first_name|tag.char.external, last_name|tag.char.external, salary|tag.nbr.external

Runtime JDBC properties can override Thales defaults. Thales-specific settings fall back to thales-config.properties.

Allowlist behavior

When enabled, the wrapper looks up the resolved database identity in a CipherTrust Manager userset before allowing reveal.

Predicate note: ordinary joins and multi-table queries can be executed and their returned fields can be revealed. The single-table limitation applies to automatic rewriting of literal predicates on protected columns.

Reads existing rows, protects or unprotects configured columns, and updates the same rows by primary key. Use it for controlled table conversion, not for ordinary end-user query access.

Authentication practice: use client credentials and an external keystore for certificate-based CipherTrust access where possible; use Akeyless when centralized secret retrieval is required. The driver selects one configured credential source and does not mix values across sources.

Deployment and Operations

DbVisualizer and standalone utility guidance

DbVisualizer deployment

Use the generated target/dbvisualizer-libs/ layout. Copy every jar from that directory into one driver definition, including the thin wrapper jar and all runtime dependencies.

  • Use thales-snowflake-jdbc-plugin-1.0.0.jar from that folder.
  • Keep the matching Snowflake JDBC, CADP, JNA, Bouncy Castle, OkHttp, Kotlin, logging, and other dependency jars together.
  • Do not mix old jars, duplicate artifacts, or use the -all / -dbvis output instead.
  • Restart or reconnect DbVisualizer after updating driver files.

Session context

Set the appropriate Snowflake warehouse, database, schema, and role. Warehouse selection is session-specific.

CSV loader modes

ModeUse
protect-and-loadPlain CSV input for configured internal-policy fields.
load-onlyPre-protected BDT output, including per-row external *_HEADER fields.

The loader reads the CSV header, validates it against the Snowflake target, and performs named-column inserts. CSV order does not need to match the table-definition order.

In-place transformation utility

DataTransformColumnsInPlace uses dbprotect.target.table and dbprotect.batch.size. Configure exactly one operation per run:

  • app.dbnewfieldstoprotect protects existing values in place.
  • app.dbfieldstounprotect unprotects existing values in place.
  • The utility uses the table primary key to update the original rows after processing each batch.
Utility workflow: use SnowflakeWrapperTest to validate the wrapper against a representative query, use DataLoadCsvToDB to load sample or BDT-protected data, and use DataTransformColumnsInPlace only when an existing table must be transformed in place.
