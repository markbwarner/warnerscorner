Thales Client-Side End-to-End Protection

Protect Sensitive Data Where It Is Captured

This document describes a Thales CipherTrust design pattern for protecting sensitive data directly on the client device: browser, mobile app, kiosk, or IoT capture point. The goal is to reduce exposure before data crosses the network, before backend middleware handles it, and before downstream systems persist it.

Plain-language summary. Sensitive values are encrypted at the source using a one-time browser-generated AES key. That AES key is wrapped with a Thales-managed public key, sent to the backend with the encrypted fields, unwrapped by a trusted backend service, and then re-protected with Thales CRDP before storage or downstream processing.

A common way to describe this is "at the glass": securing sensitive data where the user's fingertips touch the screen. In a web application, that means encryption happens inside the browser interface before the data is sent to the server. In a mobile, kiosk, or IoT design, the same idea applies at the capture application.

Business outcome Keep plaintext out of more places: browser-to-server transit, reverse proxies, middleware logs, message queues, temporary files, and databases. The design narrows where sensitive data can exist in clear form and gives the organization a controlled re-protection point on the backend.

How It Works

1. Security at the Source

The client application creates a single-use symmetric key using platform cryptography such as the browser Web Crypto API. Sensitive fields such as name, address, account number, payment card number, national ID, or health data are encrypted immediately on the client.

  • The client generates one AES key for the submission.
  • Each sensitive field is encrypted separately, usually with its own initialization vector.
  • The AES key is wrapped with a Thales-managed public key.
  • The private key is never exposed to the browser or client application.

2. Scaling the Front Door

In a production design, the public key can be served from a fast backend cache such as Redis. The backend can pre-fetch public-key material from CipherTrust Manager and serve it to thousands of users without making the browser contact the key manager directly.

  • Public keys are safe to distribute, but should still be versioned and governed.
  • Redis or another low-latency cache removes public-key lookup pressure from CipherTrust Manager.
  • The browser receives the public key quickly without learning backend credentials.
  • Key rotation can be managed by cache expiry, key version metadata, and controlled backend refresh.

3. Trusted Backend Transition

The backend receives the encrypted payload and the wrapped AES key. It authenticates to Thales CipherTrust Manager using backend-only credentials, unwraps the AES key through REST or CADP, decrypts the field values in memory, and then immediately applies durable protection.

  • The backend should avoid logging cleartext or writing it to temporary storage.
  • The plaintext window is intentionally brief and limited to the trusted processing boundary.
  • CRDP can re-protect values using format-preserving or tokenization-style policies.
  • Protected values can preserve database shape, indexing strategy, and downstream application compatibility.

Business Benefits

Benefit What It Means Why Application Teams Care
Reduced attack surface Sensitive data is protected before normal backend routing, logging, and persistence. Fewer systems need to be treated as places where cleartext may appear.
Separation of duties The browser can encrypt with a public key, but only trusted backend services can unwrap. Frontend teams do not need private keys or key-manager credentials.
High-scale public-key distribution Public key retrieval can be cached behind the application backend. Large retail or consumer workloads do not need each browser to call the KMS.
Storage and analytics compatibility CRDP can protect fields into values that preserve useful formats. Applications can keep existing schemas, indexes, file layouts, and many downstream integrations.
Consistent enterprise controls Keys, policies, audit, and administrative control remain in Thales infrastructure. Security teams retain centralized governance while application teams keep familiar development patterns.

Common Use Cases

Retail and Payment Capture

Protect payment card, loyalty, address, and order data before it reaches ecommerce middleware or order-management systems.

Financial Services Onboarding

Protect account applications, tax identifiers, bank details, beneficiary data, and identity attributes at capture time.

Healthcare Portals

Encrypt patient attributes, insurance details, intake forms, and sensitive comments before portal traffic reaches backend systems.

Call Center and Kiosk Entry

Limit exposure in assisted channels where sensitive data may pass through browser sessions, desktop tools, or kiosk workflows.

Mobile and Field Apps

Use the same envelope-protection pattern in mobile apps, handheld devices, and field data collection workflows.

IoT and Edge Capture

Protect sensitive measurements, device identifiers, or regulated data before transmission from edge devices.

What This Demo Shows

The current prototype demonstrates the core browser-to-backend lifecycle:

  • Browser-side field encryption with a one-time AES key.
  • Public-key wrapping of that AES key using a Thales-managed RSA public key.
  • Backend unwrap using either CipherTrust REST or CADP.
  • Backend reconstruction of the original payload for the trusted processing step.
  • Backend CRDP protect and reveal operations for downstream policy-based protection.
Prototype note. This demo proves the pattern, but a production deployment should add hardened TLS, certificate validation, strict logging controls, secure credential management, Redis or equivalent key caching if needed, operational monitoring, and formal threat-model review.

Positioning Statement

Thales Client-Side End-to-End Protection helps organizations move sensitive-data protection closer to the moment of capture while still using enterprise-grade Thales key management and CRDP policy enforcement on the backend. It gives application teams a practical way to reduce plaintext exposure without requiring every downstream system to become a cryptographic system.
