Why it matters

In a multi-agent application, each handoff can expose data to another service. A trip planner can work with a protected fax reference. The fax service needs the destination to make the handoff. In an insurance workflow, an approval step can use a protected customer identifier while a payment integration has a different need for the underlying banking data.

Protect A2A puts admission, routing, and data handling in shared services. The orchestrator determines the business sequence. Each agent card describes the agent’s identity, address, skills, and data policy. The gateway uses the verified card to determine how to deliver the request.

CipherTrust Manager provides trust records for registration. CipherTrust RESTful Data Protection (CRDP) performs the protect and reveal operations requested at runtime.

Workflow examples

What the receiving agent sees

Each orchestrator calls a series of agents through the gateway. The receiving agent’s policy determines the data handling for that request. Protected references can travel in a result and be used as input to a subsequent step.

Travel planning and fax handoff

Follow the fax reference across two calls. The trip orchestrator includes it with the planner input. The planner uses the protected reference in the itinerary. When the orchestrator sends that itinerary to the fax agent, the gateway asks CRDP to resolve recognized tokens under the fax identity. The demo fax handler returns a confirmation and the text it received.

Questions the report can answer

  • Did the registry accept the agent’s identity and declared mode?
  • Did the gateway find the target and admit the call under the rate limit?
  • Did a protection attempt lead to agent delivery, and how many values were marked for handling?

What a customer evaluation can validate

  • Onboard approved service identities and confirm expected registry denials.
  • Compare the input seen by an agent that needs a protected reference with the input needed by a reveal-enabled destination.
  • Trace the result from the gateway event to the CRDP entry and the agent response.

What teams take into design review

A map of the agent call path, the fields each role needs, the points where CipherTrust applies protection, and the audit events that support review. Use that evidence to define destination authorization, authenticated transport, reveal failure handling, and log retention for a production integration.
